# Revisión de seguridad, arquitectura y rendimiento — 1 de octubre de 2026

## Cambios aplicados

- Se sustituyó la versión vulnerable de `deepmerge-ts` usada por la cadena de Prisma. `pnpm audit --audit-level moderate` ya no reporta vulnerabilidades conocidas.
- La API envía CSP, protección contra iframes y MIME sniffing, política de referencias y caché privada para rutas de administración. HSTS se activa en producción.
- El vencimiento de reservas se aisló en un módulo y las peticiones simultáneas comparten una sola ejecución. Se conserva la actualización transaccional que solo libera números si la reserva sigue activa y vencida.
- Se limitan a 200 las conexiones SSE simultáneas por proceso. La subida de fotos usa una transacción serializable para evitar superar el límite de cinco con cargas concurrentes.
- Las nuevas URL de imagen solo aceptan HTTPS. La búsqueda de números en el panel espera 250 ms tras escribir antes de consultar la API.

## Verificaciones ejecutadas

- `pnpm --filter @cifraya/api test`: 6 pruebas aprobadas, incluyendo sesiones HMAC, cabeceras y coordinación del vencimiento.
- `pnpm build`: API y web compilan.
- `pnpm audit --audit-level moderate`: sin vulnerabilidades conocidas.
- `git diff --check`: sin errores de formato.
- Grafo de arquitectura regenerado con Graphify.

## Límites y tareas antes de producción

- No se ejecutaron pruebas de concurrencia ni de extremo a extremo contra PostgreSQL: Docker/PostgreSQL local no están disponibles. No se debe usar la base de producción para estas pruebas. Antes de abrir ventas, probar dos reservas del mismo número, vencimiento simultáneo con comprobante, doble carga de comprobante y confirmaciones concurrentes en una base de ensayo.
- El PIN de seis dígitos se ha compartido durante el desarrollo. Debe rotarse antes de producción. El límite de intentos de acceso vive en memoria del proceso; no sustituye MFA ni un límite persistente en el borde de red.
- El plan gratuito de Render puede suspender el servicio por inactividad; la aplicación no garantiza disponibilidad continua 24/7.
- Los comprobantes y fotos se guardan en PostgreSQL. Vigilar tamaño de la base y considerar almacenamiento de objetos con copias de seguridad y política de retención antes de crecer.
